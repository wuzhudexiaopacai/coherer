## 1. 项目背景与目标

### 1.1 背景

企业物联网场景需要一套统一的设备接入与数据管理平台：设备经 MQTT 接入，按物模型规范化数据，进行时序存储与查询、规则告警、远程升级与可视化运营。本项目对标阿里云 IoT 平台 / ThingsBoard，以自研方式实现核心能力，既用于求职展示，也按生产级标准设计和演进。

### 1.2 目标

1. 覆盖**设备全生命周期**：注册 → 认证接入 → 上报 → 存储 → 查询 → 控制 → 告警 → OTA。
2. 技术栈对齐国内企业主流：Java 21 + Spring Boot 3 + Spring Cloud Alibaba、EMQX、Kafka、TDengine。
3. 无嵌入式经验的前提下，用**设备模拟器**完成端到端验证；平台侧不依赖真实硬件。
4. 具备可量化的性能指标（压测报告）与可部署形态（Docker Compose → Kubernetes）。

### 1.3 术语表

| 术语 | 说明 |
|---|---|
| 物模型 TSL | 对设备能力的数字化描述：属性（Property）、事件（Event）、服务（Service） |
| 设备影子 | 设备状态的云端副本：desired（期望状态）与 reported（上报状态） |
| QoS | MQTT 消息服务质量等级（0 至多一次 / 1 至少一次 / 2 恰好一次） |
| LWT | Last Will and Testament，遗嘱消息：设备异常断连时由 Broker 代发 |
| 共享订阅 | `$share/group/topic`，多个消费者分摊同一主题的订阅，实现水平扩展 |
| 一机一密 | 每台设备独立密钥，签名认证接入 |
| OTA | Over-The-Air，远程固件升级 |

## 4. 核心用户故事与验收标准

### US-01 设备接入（一机一密）

> 作为**开发者**，我注册设备后能拿到 deviceId 与密钥，设备用它签名连接 EMQX，平台校验通过后允许接入。

**验收标准**
- 注册接口返回 deviceId 与一次性明文密钥，数据库中只有密文（认证时解密校验 HMAC）；
- 正确签名可建立连接，错误签名/过期时间戳（±5 分钟）被拒绝且返回原因；
- 禁用设备无法连接；
- 同一设备重复连接（多客户端）按策略处理（后踢前，可配置）。

### US-02 遥测上报与查询

> 作为**运维**，我能看到设备的实时数据和历史曲线。

**验收标准**
- 设备上报 QoS1 消息，端到端（发布 → 入库）P99 < 500ms；
- 看板实时曲线秒级更新；
- 历史查询支持 1h/24h/7d 与聚合粒度，响应 < 2s；
- 非法遥测（缺字段/类型错）被丢弃并在审计中可查。

### US-03 命令下发

> 作为**运维**，我能在设备详情页下发重启命令并看到结果。

**验收标准**
- 在线设备 1s 内收到命令（P99）；
- 设备回复后命令状态置为成功，耗时可见；
- 设备离线/超时：展示超时状态，按配置重试后失败；
- 重复下发同一 messageId 不会导致设备重复执行（幂等）。

### US-04 阈值告警

> 作为**运维**，温度持续超过 80℃ 10 秒时我能收到告警通知。

**验收标准**
- 规则可配置属性、比较符、阈值、持续时间、级别；
- 触发后生成告警记录并通知（邮件/钉钉）；
- 数值恢复后自动置为已恢复；同规则短时间重复触发去重。

### US-05 OTA 升级

> 作为**运维**，我能对一批设备发起灰度升级并跟踪进度。

**验收标准**
- 固件上传校验 SHA-256；
- 任务按批次下发，批次完成后再进入下一批；
- 每台设备进度/状态可查；
- 失败设备不影响其他设备，任务最终状态正确（成功/部分成功/失败）。

### US-06 设备影子

> 作为**开发者**，设备离线时我设置期望值，设备上线后自动同步。

**验收标准**
- 设置 desired 后设备上线收到属性设置指令；
- 设备上报 reported 后影子版本号递增；
- 并发更新时基于版本号乐观锁，冲突可识别。

## 5. 非功能需求

| 类别 | 指标 | 说明 |
|---|---|---|
| 接入规模 | 单集群 ≥ 10 万并发 MQTT 连接 | EMQX 集群 + emqtt-bench 压测验证 |
| 吞吐 | 上行 ≥ 5 万 msg/s | 单机压测口径，写入批量与异步化 |
| 延迟 | 设备→入库 P99 < 500ms；命令下发 P99 < 1s | 端到端测量，含 Kafka 链路 |
| 可用性 | 99.9%（生产形态） | K8s 多副本 + 中间件高可用 |
| 安全 | 传输 TLS 1.2+；密码 bcrypt；设备密钥 PBKDF2/哈希存储；ACL 最小权限 | 生产配置项可开关 |
| 数据保留 | 原始遥测 90 天可配置；聚合数据长期 | TDengine 数据保留策略 |
| 可观测 | 核心链路指标 + 结构化日志 + trace-id | Prometheus/Grafana |
| 兼容性 | MQTT 3.1.1 / 5.0；Chrome/Edge 最新版 | 设备侧兼容旧协议 |
| 可维护性 | 单测覆盖核心服务；OpenAPI 文档；一键本地启动 | |

## 7. 约束与假设

1. **无真实硬件**：开发和验证全部基于 Python 模拟器；后期可选 ESP32 真机演示。
2. **单区域部署**：不做跨地域容灾；K8s 场景为单集群。
3. **中等规模目标**：以 10 万连接、5 万 msg/s 为压测目标，不做超大规模多集群联邦。
4. **租户隔离**：先逻辑隔离（tenant_id 贯穿 + 主题前缀），物理隔离不在范围内。
5. **不实现设备端 SDK**：提供协议文档与模拟器示例，真实设备按协议接入。
